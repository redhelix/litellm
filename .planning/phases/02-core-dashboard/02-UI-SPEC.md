# Phase 2 — UI Design Contract: Core Dashboard

> Visual and interaction contract for the Core Dashboard frontend. Generated by
> gsd-ui-researcher. Verified by gsd-ui-checker before implementation begins.

This is a **local lab monitoring dashboard** — not a SaaS product. One user,
LAN-only, no authentication. Optimised for glanceability at a single screen.

## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap, badge internal padding |
| sm | 8px | Inline padding in compact metric cells, table row padding |
| md | 16px | Card internal padding, default element spacing |
| lg | 24px | Section padding, grid gap between cards |
| xl | 32px | Gap between major layout sections (overview → node grid) |
| 2xl | 48px | Vertical page padding (top/bottom of content area) |
| 3xl | 64px | Not used in Phase 2 |

Exceptions:
- Node status indicator dots: 10px × 10px (not on 4-point scale — matches
  common status-dot convention for clear readability)
- Touch targets for any clickable element: minimum 44px height (accessibility
  floor, even for desktop-only tool)

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 14px | 400 (regular) | 1.5 | Table cell content, node last-seen timestamps |
| Label | 12px | 500 (medium) | 1.4 | Metric labels ("p50 TTFT", "tokens/sec"), column headers, badge text |
| Heading | 18px | 600 (semibold) | 1.2 | Section headings ("Overview", "Node Health") |
| Display | 28px | 700 (bold) | 1.1 | Primary aggregate metric values (e.g., "142ms") |

Two weights in use for normal content: 400 body + 600 semibold.
500 and 700 are edge-case weights used only for labels and display numbers
respectively — they do not count as additional general-purpose weights.

Monospace stack (for latency values and request IDs): `font-mono`
(ui-monospace, Cascadia Code, Menlo, monospace). Applied to all numeric
metric values in the overview panel and per-model cards.

## Color

Dark theme. The dashboard is a lab tool viewed at a glance — high-contrast
dark surfaces reduce eye strain and make status colours pop.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a0a` (zinc-950) | Page background, header background |
| Secondary (30%) | `#18181b` (zinc-900) | Cards, node grid cells, metric panels |
| Accent (10%) | `#3b82f6` (blue-500) | See reserved list below |
| Success | `#22c55e` (green-500) | Healthy node status dot, tool call success rate bar segment |
| Warning | `#f59e0b` (amber-500) | Slow node status dot, tool call repaired rate bar segment |
| Destructive | `#ef4444` (red-500) | Unreachable node status dot, tool call failed rate bar segment, error states |
| Muted text | `#71717a` (zinc-500) | Secondary labels, timestamps, "last seen" copy |
| Border | `#27272a` (zinc-800) | Card borders, dividers, table row separators |
| Foreground | `#fafafa` (zinc-50) | All primary text on dark surfaces |

**Accent (`#3b82f6`) reserved for:**
1. The auto-refresh countdown ring/indicator
2. Currently selected model (if a model card is focused/selected)
3. External link icons (if any docs links appear)

Accent is NOT used for: metric values, status indicators, table headers, or
navigation elements. Status colours (green/amber/red) carry all semantic
meaning for node and tool call states.

**Tool call 3-state colour mapping is fixed:**
- `success` → green-500
- `repaired` → amber-500
- `failed` → red-500

These three colours must be used consistently across every surface that
displays tool call state (overview bar, per-model card, stacked bar).

│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────────┐  │
│  │p50   │ │p95   │ │tok/s │ │ctx % │ │tool call │  │
│  │TTFT  │ │total │ │      │ │      │ │3-state   │  │
│  └──────┘ └──────┘ └──────┘ └──────┘ └──────────┘  │
├─────────────────────────────────────────────────────┤

│  ┌─────────────────┐  ┌─────────────────┐           │
│  │ model-alias     │  │ model-alias     │  ...       │
│  │ p50/p95 TTFT    │  │ p50/p95 TTFT    │           │
│  │ p50/p95 latency │  │ p50/p95 latency │           │
│  │ tok/s  ctx%     │  │ tok/s  ctx%     │           │

## Data Display Contracts

### Metric Value Formatting

| Metric | Format | Example | Null handling |
|--------|--------|---------|---------------|
| TTFT p50 / p95 | integer ms, no decimals | `142ms` / `380ms` | Show `—` |
| Total latency p50 / p95 | integer ms, no decimals | `510ms` / `1,240ms` | Show `—` |
| Tokens/sec | 1 decimal place | `23.4 tok/s` | Show `—` |
| Context utilization % | integer % | `67%` | Show `—` |
| Tool call success rate | integer % per state | `82% / 12% / 6%` | Show `0%` |
| Node last request | relative time | `3 min ago` | Show `never` |

All numeric metric values use `font-mono`. Values ≥1000ms use comma separator
(`1,240ms`). Never show raw JSON or API response objects in the UI.

### Node Status Rules (VIEW-02)

The node `availability_status` field from `GET /api/nodes` maps to display as:

| API value | Badge label | Badge colour | Status dot |
|-----------|-------------|--------------|------------|
| `healthy` | `healthy` | green bg, white text | green-500 |
| `slow` | `slow` | amber bg, black text | amber-500 |
| `unreachable` | `unreachable` | red bg, white text | red-500 |
| `unknown` | `unknown` | zinc-700 bg, zinc-300 text | zinc-500 |

If `last_scrape` timestamp is more than 90 seconds old, override displayed
status to `unknown` regardless of API value.

### Auto-Refresh Contract (SYS-03 + success criterion 1)

- Interval: 30 seconds
- Mechanism: `setInterval` calling `Promise.all([fetchModels(), fetchNodes()])`
- Countdown ring visible in header, resets to full on each successful fetch
- On fetch error: ring stops, header shows `Connection lost — retrying…` in
  amber-500; retry every 10 seconds
- No page reload. No user interaction required to trigger refresh.
- Stale data indicator: if last successful fetch is >60 seconds ago, all
  metric values dim to `opacity-50` and a banner reads `Data may be stale`

## Interaction Contract

Phase 2 is a read-only monitoring surface. Interactions are minimal:

| Interaction | Behaviour |
|-------------|-----------|
| Hover metric value | Tooltip shows full breakdown (e.g., "p50: 142ms from 847 requests in last 5m") |
| Hover tool call bar segment | Tooltip shows count and percentage for that state |
| Hover node row | No additional action — hover state: `bg-zinc-800` row highlight |
| Click model card | No navigation in Phase 2 — card is not clickable. Cursor: default. |
| Click node row | No action — Phase 2 only. Do not add disabled click handlers. |
| Page load | Immediate fetch on mount; spinner in each card slot while loading |
| Keyboard navigation | All interactive elements (tooltips) must be reachable via Tab and triggerable via Enter/Space |

Loading state per card: show a subtle `animate-pulse` skeleton in the value
position (not a full card skeleton). The card frame and labels render
immediately; only the numeric values pulse.

## Accessibility

- Colour is never the sole indicator of state. Every status badge has a text
  label in addition to the colour.
- Status dots (colour-only) are supplementary to the badge — they are
  `aria-hidden="true"`.
- All `<Card>` metric panels have an `aria-label` matching the section heading
  + metric name (e.g., `aria-label="Overview p50 TTFT"`).
- Tooltip triggers have `aria-describedby` linking to tooltip content.
- Auto-refresh countdown has `aria-label="Auto-refreshes in {N} seconds"` and
  uses `aria-live="polite"` for the connection-lost banner.
- Contrast: all text on `zinc-900` background meets WCAG AA (4.5:1 minimum).
  `zinc-50` on `zinc-900` = ~16:1 (far exceeds AA).
