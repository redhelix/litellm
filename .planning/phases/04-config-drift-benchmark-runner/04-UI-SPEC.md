# Phase 4 — UI Design Contract: Config Drift + Benchmark Runner

> Visual and interaction contract for the Config Drift view and Benchmark
> Runner panel. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase appends two new sections to the single-page dashboard below the
existing Trends section. No new routes. No layout restructuring. All tokens,
colours, and typography are inherited from Phases 2 and 3 and confirmed below.

Phase 4 introduces the first **user-initiated write action** (benchmark trigger)
and the first **security-semantic display** (hardcoded master key warning).
Both require new interaction and visual contracts defined in this document.

Requirements covered: DRIFT-01, DRIFT-02, DRIFT-03, DRIFT-04, BENCH-01,
BENCH-02, BENCH-03.

## Color

Dark theme. All tokens inherited from Phase 2 and confirmed in index.css.
Phase 4 adds one new semantic colour role: **security warning**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.145 0 0)` (~zinc-950) | Page background — unchanged |
| Secondary (30%) | `oklch(0.205 0 0)` (~zinc-900) | Cards, diff panel background, benchmark card |
| Accent (10%) | `#3b82f6` blue-500 | See reserved list below |
| Success | `#22c55e` green-500 | Benchmark result: latency within acceptable range; config key: matches repo |
| Warning | `#f59e0b` amber-500 | Drift items: routing strategy mismatch, max_tokens difference, missing backends |
| Destructive | `#ef4444` red-500 | Config key: failed value or missing entirely; benchmark error |
| Security | `#f97316` orange-500 | Hardcoded master key warning ONLY — see DRIFT-02 |
| Muted text | `oklch(0.708 0 0)` (~zinc-500) | Config path labels, benchmark history timestamps |
| Border | `oklch(1 0 0 / 10%)` | Card borders, diff row separators |
| Foreground | `oklch(0.985 0 0)` (~zinc-50) | All primary text |

**Accent (`#3b82f6` / blue-500) reserved for:**
1. The auto-refresh countdown ring (Phase 2, unchanged)
2. "Run benchmark" button active/focus ring
3. Currently running benchmark row highlight (pulsing border)

Accent is NOT used for: drift item indicators, security warnings, table
headers, or benchmark result values. Semantic meaning is carried by
green/amber/red/orange.

**Security colour (`#f97316` / orange-500) reserved for DRIFT-02 ONLY:**
The hardcoded master key drift item. This is the sole use of orange in the
entire dashboard. It must not be used for any other element. Orange-500 is
visually distinct from amber-500 (warning) and red-500 (error) to signal
"security concern" rather than "performance problem" or "failure."

**Drift severity colour mapping (fixed):**
- Security issue (master key) → orange-500
- Functional mismatch (routing strategy, max_tokens, missing backend) → amber-500
- Key present in repo but missing from deployed → red-500
- Key matches exactly → green-500 (shown only as a confirmation row if user
  requests "show all", not by default)

**Benchmark result colour mapping:**
- TTFT or latency below p95 historical threshold → green-500 (text)
- TTFT or latency above p95 historical threshold → amber-500 (text)
- Request failed / timeout → red-500 (text)
- In-progress / running → muted-foreground with `animate-pulse`

## Data Display Contracts

### Config Drift View (DRIFT-01, DRIFT-02, DRIFT-03, DRIFT-04)

Endpoint: `GET /api/config/diff`

Expected response shape (for frontend contract — backend defines exact schema):

```ts
interface DriftItem {
  key_path: string          // e.g. "router_settings.routing_strategy"
  deployed_value: string    // current value on docker-001
  repo_value: string        // value in local repo version
  severity: 'security' | 'mismatch' | 'missing'
}

interface ConfigDiffResponse {
  items: DriftItem[]
  last_checked: string      // ISO timestamp
}
```

**Diff row display:**

Each `DriftItem` renders as a single row in the drift panel:

| Field | Display |
|-------|---------|
| `severity: 'security'` | Orange `Alert` component (full-width, prominent) at top of list before all other items |
| `severity: 'mismatch'` | Amber `△` icon + key path in `font-mono text-sm` + two-line value comparison |
| `severity: 'missing'` | Red `✗` icon + key path + "Not in deployed config" label |

**Security item (DRIFT-02) — separate treatment:**
- Rendered as a full-width `<Alert variant="destructive">` using orange-500
  background tint (`bg-orange-500/10 border-orange-500/30`) at the very top of
  the drift list, before mismatch and missing items
- `AlertTitle`: `Security: hardcoded master_key detected`
- `AlertDescription`: `The deployed config.yaml contains a hardcoded
  master_key. Rotate this key and use an environment variable before
  production deployment.`
- Does not show "deployed value" inline — never render the key value in the UI

**Value comparison layout for mismatch rows:**
```
key_path (font-mono text-sm text-zinc-400)
  Deployed: {deployed_value}  →  Repo: {repo_value}
            (amber-500 text)      (foreground text)
```

Both values use `font-mono text-sm`. Long values truncate at 40ch with a
`Tooltip` showing the full value on hover.

**Default display:** Show only `security` and `mismatch` and `missing` items.
Do not show matching keys. No "show all" toggle in Phase 4.

**Item count in section header:** `{N} differences` where N is
`items.length`. If `items.length === 0`, show `No differences detected`.

**Last-checked timestamp:** Shown below the diff list in `text-xs text-zinc-500`:
`Last checked: {relative time}` with tooltip showing ISO timestamp.

### Benchmark Runner (BENCH-01, BENCH-02, BENCH-03)

**Trigger endpoint:** `POST /api/benchmark/run`

**Results endpoint:** `GET /api/benchmark/latest` (most recent run results)

**History endpoint:** `GET /api/benchmark/history?limit=10`

Expected result shape:

```ts
interface BenchmarkResult {
  model: string
  ttft_ms: number | null
  total_latency_ms: number | null
  tokens_per_sec: number | null
  status: 'ok' | 'error' | 'timeout'
  error_message?: string
}

interface BenchmarkRun {
  run_id: string
  started_at: string        // ISO timestamp
  completed_at: string | null
  results: BenchmarkResult[]
}

interface BenchmarkHistoryResponse {
  runs: BenchmarkRun[]
}
```

**Results table columns:**

| Column | Header text | Data field | Format | Width |
|--------|-------------|------------|--------|-------|
| Model | `Model` | `model` | `font-mono text-sm` truncated at 24ch | ~30% |
| TTFT | `TTFT` | `ttft_ms` | integer ms, `font-mono` | ~15% |
| Latency | `Latency` | `total_latency_ms` | integer ms, `font-mono` | ~15% |
| Throughput | `tok/s` | `tokens_per_sec` | 1 decimal, `font-mono` | ~15% |
| Status | `Status` | `status` | Badge (see below) | ~15% |

**Status badge colour mapping:**
- `ok` → `bg-green-500/20 text-green-400 border-green-500/30`
- `error` → `bg-red-500/20 text-red-400 border-red-500/30`
- `timeout` → `bg-amber-500/20 text-amber-400 border-amber-500/30`
- in-progress (row being tested) → `bg-zinc-700/40 text-zinc-400` with
  `animate-pulse`

Null values in numeric columns: `—` (em-dash, same as all prior phases).

**Benchmark history list:**

Below the results table, a collapsed list of up to 10 prior runs:

| Field | Display |
|-------|---------|
| Run identifier | `Run #{N}` (sequential number, newest first) |
| Timestamp | Relative time + ISO tooltip (same pattern as request log) |
| Expand action | Click row → replace results table with that run's results |
| "Back to latest" | Link/button appears when viewing a historical run |

Selected history row: `bg-zinc-800` highlight (same hover pattern used across
all tables in the dashboard).

## Interaction Contract

Phase 4 introduces the dashboard's first user-initiated action with a side
effect (the benchmark trigger). Config drift is read-only.

| Interaction | Behaviour |
|-------------|-----------|
| Page mount — config drift | Fetch `/api/config/diff` immediately; show `animate-pulse` skeleton in diff list while loading |
| Page mount — benchmark | Fetch `/api/benchmark/latest` and `/api/benchmark/history?limit=10` immediately; show latest results if any exist |
| Click "Run benchmark" | Open `AlertDialog` confirmation; do NOT fire the request yet |
| Click "Cancel" in dialog | Close dialog; no request fired; button returns to idle |
| Click "Run benchmark" in dialog | Close dialog; POST `/api/benchmark/run`; button enters disabled state with label `Running…`; all result rows enter `animate-pulse` status |
| Benchmark in-progress | "Run benchmark" button is `disabled`, `opacity-70`, `cursor-not-allowed`; poll `/api/benchmark/latest` every 5 seconds until `completed_at` is not null |
| Benchmark complete | Stop polling; render final results table; show green/amber/red status badges; re-enable "Run benchmark" button; add new run to history list |
| Benchmark error (request fails) | Show error toast (shadcn `Sonner` or equivalent): `Benchmark failed to start — check that dashboard-sidecar is running on docker-001:4001.`; re-enable button |
| Click history run row | Replace results table content with historical run results; show "← Back to latest" link above table |
| Click "← Back to latest" | Restore latest run results; remove history row highlight; hide "← Back to latest" link |
| Hover diff row | `bg-zinc-800` row highlight (same as all tables) |
| Hover config value (truncated) | Tooltip shows full value |
| Hover diff last-checked timestamp | Tooltip shows ISO-8601 UTC timestamp |
| Hover benchmark result timestamp | Tooltip shows ISO-8601 UTC timestamp |
| Hover benchmark error status badge | Tooltip shows `error_message` (full, untruncated) |
| Hover benchmark result latency value | Tooltip shows `{ttft_ms}ms TTFT / {total_latency_ms}ms total` (contextual breakdown) |
| Keyboard navigation | "Run benchmark" button reachable via Tab, triggerable via Enter/Space; AlertDialog traps focus within modal; history rows focusable via Tab |

**Benchmark "Run benchmark" button state machine:**

```
idle  →  [click]  →  confirming (AlertDialog open)
confirming  →  [cancel]  →  idle
confirming  →  [confirm]  →  running (disabled, "Running…", polling)
running  →  [complete]  →  idle (results updated)
running  →  [error]  →  idle (error toast shown)
```

**Config drift does not auto-refresh.** It fetches once on mount. No
re-fetch on the 30-second auto-refresh interval (config diffs are not
time-sensitive in the same way as live metrics). A manual page reload
will re-fetch.

**Auto-refresh (30-second interval from Phase 2) does NOT re-fetch** config
drift or benchmark results. The polling mechanism added for benchmark
in-progress state (5-second interval) is separate and terminates when the run
completes.

## Accessibility

Inherits all Phase 2 and Phase 3 accessibility rules, plus:

- Security `<Alert>` has `role="alert"` so screen readers announce it
  immediately on load
- "Run benchmark" `<Button>` has `aria-label="Run benchmark across all models"`
  in idle state and `aria-label="Benchmark in progress"` in running state
- `<AlertDialog>` traps focus within the modal when open; `Escape` key closes
  without firing the request (same as clicking Cancel)
- `AlertDialogAction` ("Run benchmark") has `aria-label="Confirm: run benchmark"`
- Diff row list has `role="list"` and each row has `role="listitem"`
- Severity icons (△, ✗, ⚠) are `aria-hidden="true"` — text labels (`MISMATCH`,
  `MISSING`, `SECURITY`) are the accessible indicator, not the icon
- History run rows that are buttons have `aria-label="View results for Run #{N},
  started {timestamp}"`
- Colour is not the sole indicator of severity — every diff item has a text
  severity label in addition to the colour coding
- Benchmark status badges contain text labels (`ok`, `error`, `timeout`,
  `Running…`) — colour is supplementary
