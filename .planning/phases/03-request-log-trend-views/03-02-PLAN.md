    Create dashboard-sidecar/routers/trends.py as a new file. Follow the EXACT same pattern as routers/latency.py (WINDOW_TO_SQL allowlist, HTTPException on invalid window, parameterised query).

    trends.py content:
    ```python
    from fastapi import APIRouter, HTTPException, Query
    from db import query

    router = APIRouter(prefix="/api", tags=["trends"])

    WINDOW_TO_SQL = {
        "7d":  "startTime > NOW() - INTERVAL 7 DAY",
        "30d": "startTime > NOW() - INTERVAL 30 DAY",
    }

    @router.get("/trends")
    def get_trends(model: str = Query(...), window: str = Query("7d")):
        if window not in WINDOW_TO_SQL:
            raise HTTPException(status_code=400, detail="invalid window — must be 7d or 30d")
        sql = f"""
            SELECT
                CAST(DATE_TRUNC('day', startTime) AS DATE) AS day,
                PERCENTILE_CONT(0.95) WITHIN GROUP (ORDER BY total_latency_ms) AS latency_p95,
                AVG(context_utilization)                                         AS avg_context_utilization,
                SUM(CASE WHEN tool_call_status IN ('failed','repaired') THEN 1 ELSE 0 END)::DOUBLE
                    / NULLIF(COUNT(*), 0)                                        AS error_repair_rate
            FROM requests
            WHERE {WINDOW_TO_SQL[window]} AND model = ?
            GROUP BY 1
            ORDER BY 1 ASC
        """
        rows = query(sql, (model,))
        cols = ["day", "latency_p95", "avg_context_utilization", "error_repair_rate"]
        series = []
        for r in rows:
            row_dict = dict(zip(cols, r))
            # Convert date to ISO string for JSON serialization
            row_dict["day"] = str(row_dict["day"])
            series.append(row_dict)
        return {"model": model, "window": window, "series": series}
    ```

    CRITICAL security notes (per T-03-02-01, T-03-02-02):
    - model is passed as SQL parameter `(model,)` — never f-string interpolated
    - WINDOW_TO_SQL provides only pre-approved SQL fragments — window value never touches SQL directly

    Then update dashboard-sidecar/main.py:

    - Add registration: `app.include_router(trends_router)` — place after existing include_router calls

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → FastAPI | Untrusted query params arrive at /api/requests and /api/trends |
| FastAPI handler → DuckDB | SQL built with WINDOW_TO_SQL; model/params passed as parameterised values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02-01 | Tampering | /api/requests model param | mitigate | model passed as query() tuple param — never interpolated into SQL string. `query(sql, (model,))` pattern from research. |
| T-03-02-02 | Tampering | /api/trends window param | mitigate | WINDOW_TO_SQL allowlist rejects any value not in {"7d","30d"} with 400. Window value never reaches SQL. |
| T-03-02-03 | Tampering | /api/trends model param | mitigate | model passed as query() tuple param — same pattern as T-03-02-01. |
| T-03-02-04 | DoS | /api/requests unbounded offset | mitigate | offset >= 500 → 400. Prevents full-scan past 500 rows. |
| T-03-02-05 | Information Disclosure | DuckDB error messages | accept | FastAPI default 500 response; no DuckDB internals exposed in production. Low risk on local network. |
</threat_model>
