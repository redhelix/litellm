# Phase 3 — UI Design Contract: Request Log + Trend Views

> Visual and interaction contract for the Request Log table and Trend
> sparkline charts. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This phase extends the Phase 2 single-page dashboard with two new sections
appended below the existing Nodes section. No new routes. No layout
restructuring. All tokens, colours, and typography are inherited from Phase 2
and confirmed below.

Requirements covered: VIEW-03, VIEW-04.

## Color

Dark theme. All tokens inherited from Phase 2. No new semantic colours
introduced.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(0.145 0 0)` (~zinc-950) | Page background — unchanged |
| Secondary (30%) | `oklch(0.205 0 0)` (~zinc-900) | Cards, table header background, chart container |
| Accent (10%) | `oklch(0.269 0 0)` (~zinc-800) mapped to `#3b82f6` blue-500 for interactive elements | See reserved list below |
| Success | `#22c55e` (green-500) | Tool call success bar segment, trend line for success rate |
| Warning | `#f59e0b` (amber-500) | Tool call repaired bar segment, trend line for repair rate |
| Destructive | `#ef4444` (red-500) | Tool call failed bar segment, error/repair trend line |
| Muted text | `oklch(0.708 0 0)` (~zinc-500) | Column headers, secondary labels, chart axis text |
| Border | `oklch(1 0 0 / 10%)` | Table row separators, card borders |
| Foreground | `oklch(0.985 0 0)` (~zinc-50) | All primary text |

**Accent (`#3b82f6` / blue-500) reserved for:**
1. The active/selected model in the filter select (highlight ring)
2. The "Load more" / pagination navigation active page indicator
3. Trend chart line for latency p95 (a non-semantic value needing visual
   distinction from the semantic green/amber/red lines)

Accent is NOT used for: table headers, row hover states, timestamps, or
column sort indicators. Row hover uses `bg-zinc-800` (same as Phase 2 node
grid).

**Trend line colour mapping (fixed):**
- Latency p95 → blue-500 (`#3b82f6`)
- Context utilization → amber-500 (`#f59e0b`)
- Error/repair rate → red-500 (`#ef4444`)

These three colours must be applied consistently across all model sparklines.

## Data Display Contracts

### Request Log Table (VIEW-03)

Endpoint: `GET /api/requests?limit=25&offset={N}&model={filter}`

| Column | Header text | Data field | Format | Width |
|--------|-------------|------------|--------|-------|
| Model | `Model` | `model` | `font-mono text-sm` truncated at 24ch | ~25% |
| TTFT | `TTFT` | `ttft_ms` | integer ms, no decimals, `font-mono` | ~10% |
| Latency | `Latency` | `total_latency_ms` | integer ms, no decimals, `font-mono` | ~10% |
| Context | `Ctx %` | `context_utilization` | integer %, `font-mono` | ~8% |
| Tool call | `Tool call` | `tool_call_status` | Badge (see below) | ~12% |
| Timestamp | `Time` | `created_at` | relative time with tooltip showing ISO timestamp | ~15% |

Null values in numeric columns: show `—` (em-dash, same as Phase 2 rule).

**Tool call status badge colour mapping:**
- `success` → `bg-green-500/20 text-green-400 border-green-500/30`
- `repaired` → `bg-amber-500/20 text-amber-400 border-amber-500/30`
- `failed` → `bg-red-500/20 text-red-400 border-red-500/30`
- `null` / unknown → `bg-zinc-700/40 text-zinc-400 border-zinc-600/40`

These colour rules are identical to the Phase 2 node status badge rules —
same pattern, same Tailwind classes.

**Pagination:**
- Page size: 25 rows
- Controls: Prev button (disabled on page 1) + "Page N of M" text + Next
  button (disabled on last page)
- Row count display: `{total} requests` shown right-aligned in section header
- Max rows to query: 500 (backend bounded — do not allow unbounded queries)

**Model filter:**
- A `Select` above the table, left-aligned with the section heading
- Default value: `All models`
- Options: `All models` + one option per unique model alias from the data
- On change: reset to page 1, refetch with `model={alias}` param

**Sort:** Fixed sort order — newest first (`ORDER BY created_at DESC`). No
column sort controls in Phase 3.

### Trend Charts (VIEW-04)

Endpoint: `GET /api/trends?window=7d&model={alias}` (one request per model)

| Metric | Line colour | Y-axis | Null handling |
|--------|-------------|--------|---------------|
| Latency p95 | blue-500 | ms (hidden) | Skip point, gap in line |
| Context utilization | amber-500 | 0–1 normalised (hidden) | Skip point |
| Error/repair rate | red-500 | 0–1 normalised (hidden) | Skip point |

**Sparkline spec:**
- Width: full container width (`ResponsiveContainer width="100%"`)
- Height: 64px per model row
- No axis labels, no grid lines, no legend text below chart
- A colour key legend appears once above the chart grid:
  `— blue: latency p95  — amber: ctx utilization  — red: error/repair rate`
- Dot on hover: enabled (recharts default)
- Custom tooltip: `{date}: {value}` using recharts `<Tooltip>` with dark
  background matching `bg-zinc-900 border-zinc-800 text-zinc-50 text-xs`

**Layout for trend section:**
- One row per model alias (7 rows for 7 models)
- Each row: model name (12ch `font-mono` left column, 20% width) + sparkline
  (80% width)
- Rows separated by 1px `border-b border-zinc-800`
- The entire section is wrapped in a `Card` with `CardHeader` ("Trends") and
  `CardContent`

**Time range toggle:**
- Placement: right-aligned in `CardHeader` alongside the "Trends" heading
- Controls: `ToggleGroup` with two items: `7d` and `30d`
- Default: `7d`
- On change: re-fetch all trend series with new window param
- Active item: `bg-zinc-700 text-zinc-50`; inactive: `text-zinc-400`

**Query bound rule (success criterion 3):**
- All trend queries must use bounded date ranges: `WHERE ts > NOW() - INTERVAL`
- 30d query must not full-scan. Backend enforces this — frontend does not send
  unbounded queries (no `window=all`).

### Metric Value Formatting — Phase 3 additions

## Interaction Contract

Phase 3 introduces the first user-initiated interactions in the dashboard
(filter + pagination + time range toggle). All other views remain read-only.

| Interaction | Behaviour |
|-------------|-----------|
| Model filter change | Reset to page 1; re-fetch `/api/requests` with `model=` param; show loading state (pulse on table rows) while fetching |
| Click "Next →" | Increment page by 1; fetch next page; scroll to top of table section |
| Click "← Prev" | Decrement page by 1; fetch previous page; scroll to top of table section |
| "← Prev" on page 1 | Button is `disabled`, `opacity-50`, `cursor-not-allowed` |
| "Next →" on last page | Button is `disabled`, `opacity-50`, `cursor-not-allowed` |
| Time range toggle (7d / 30d) | Re-fetch all trend series with new window; show `animate-pulse` on sparkline rows while loading |
| Hover table row | `bg-zinc-800` row highlight (same as Phase 2 node grid) |
| Hover metric value in log table | Tooltip shows full value if truncated (e.g., full model name) |
| Hover timestamp in log table | Tooltip shows ISO-8601 UTC timestamp |
| Hover sparkline data point | Recharts built-in tooltip: `bg-zinc-900 border border-zinc-800 text-xs p-2 rounded` |
| Click table row | No action — read-only in Phase 3. Do not add disabled click handlers. |
| Keyboard navigation | Filter select, pagination buttons, and time range toggle all reachable via Tab; buttons triggerable via Enter/Space |

Loading state for request log table: show `animate-pulse` on all cell
content inside each row. The table structure (headers, borders) renders
immediately; only cell content pulses.

Loading state for trend section: show `animate-pulse` on each sparkline row's
chart area. The model name column and section heading render immediately.

Auto-refresh does NOT re-fetch the request log or trend data. These are
user-triggered views. Only the existing `/api/models` and `/api/nodes` polling
(Phase 2) continues on the 30-second interval. Request log and trends are
fetched on: mount, filter change, pagination change, and time range change.

## Accessibility

Inherits all Phase 2 accessibility rules, plus:

- Model filter `<Select>` has `aria-label="Filter by model"`
- Pagination "← Prev" button has `aria-label="Previous page"` and
  `aria-disabled="true"` when on page 1
- Pagination "Next →" button has `aria-label="Next page"` and
  `aria-disabled="true"` when on last page
- Page indicator has `aria-live="polite"` so screen readers announce page
  changes without full-page announcement
- Time range toggle group has `role="group"` and `aria-label="Trend time range"`
- Each `ToggleGroupItem` has `aria-pressed="true/false"` reflecting selection
- Trend sparkline `<LineChart>` containers have `aria-label="{model} trend chart"`
- Colour is not the sole indicator for tool call status in the log table —
  every status cell has both a coloured badge AND the text label (`success`,
  `repaired`, `failed`)
- Trend colour legend uses text labels alongside the colour swatches —
  colour alone does not encode meaning
