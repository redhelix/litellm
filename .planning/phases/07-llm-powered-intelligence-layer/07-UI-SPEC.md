## Section Layout: Intelligence Tab

The Intelligence section is a **dedicated tab** in the App.tsx tab switcher, appearing alongside the existing "Models" and "Request Log" tabs. It is gated behind a tab click — the user must navigate to the Intelligence tab to see it. This matches the user's explicit decision (D-01) and is consistent with the tab bar pattern already established in App.tsx. The tab label is "Intelligence".

### Section order within Intelligence tab (top to bottom):

```
1. Lab Health Summary          — LLM-generated prose + "last updated" timestamp
2. [Separator border-zinc-800]
3. Anomaly / Diagnosis         — list of flagged conditions, each as a Card
4. [Separator border-zinc-800]
5. Config & Model Recommendations — list of advisory recommendations, each as a Card
6. [Separator border-zinc-800]
7. HuggingFace New Models      — list of recommended models, each as a Card
8. [Separator border-zinc-800]
9. Ask a Question              — textarea + submit button + answer display
```

## Interaction Contracts

### 1. Lab Health Summary

- Displays LLM-generated prose paragraph (plain text, no markdown rendering needed).
- Shows "Last updated: Xh ago" caption in `text-xs text-zinc-500` below prose.
- Full timestamp on hover (Tooltip pattern from `RelativeTime` in RequestLogTable.tsx).
- Loading state: `animate-pulse` skeleton placeholder, same pattern as RequestLogTable loading.
- Empty/error state: see Copywriting Contract below.
- No user interaction — read-only.

### 2. Anomaly / Diagnosis Section

- Each anomaly is a `Card` with:
  - `CardHeader`: anomaly title (`text-sm font-semibold text-zinc-300`) + severity Badge (green/amber/red).
  - `CardContent`: 1-3 sentence diagnosis prose (`text-sm text-zinc-400`).
  - No action buttons — diagnose only.
- Severity Badge classes:
  - low: `bg-green-500/20 text-green-400 border border-green-500/30`
  - medium: `bg-amber-500/20 text-amber-400 border border-amber-500/30`
  - high: `bg-red-500/20 text-red-400 border border-red-500/30`
- Layout: vertical stack (`flex flex-col gap-4`), no grid.
- Empty state: see Copywriting Contract.

### 3. Config & Model Recommendations Section

- Each recommendation is a `Card` with:
  - `CardHeader`: recommendation title + mandatory "Advisory only" Badge (`bg-amber-500/20 text-amber-400 border border-amber-500/30`).
  - `CardContent`: advisory text (`text-sm text-zinc-400`).
  - No apply/action buttons — advisory display only.
- Layout: vertical stack (`flex flex-col gap-4`).
- Empty state: see Copywriting Contract.

### 4. HuggingFace New Models Section

- Each model is a `Card` with:
  - `CardTitle`: model name in `font-mono text-sm font-semibold`.
  - Meta row: size · quantization · runtime tags in `text-[11px] text-zinc-400` (matches ModelCard meta row pattern).
  - HuggingFace link: `<a href={hfUrl} target="_blank" rel="noopener noreferrer" className="text-blue-400 hover:text-blue-300 underline">View on HuggingFace</a>`.
  - 1-sentence description if available (`text-xs text-zinc-500`).
- Layout: grid — `grid grid-cols-1 md:grid-cols-2 xl:grid-cols-3 gap-6` (matches ModelCard grid in App.tsx).
- Empty state: see Copywriting Contract.

### 5. Ask a Question (Single-Shot Q&A)

- `<Textarea>` (shadcn) for question input. Rows: 3. Placeholder: "Ask about your lab metrics…"
- `<Button>` variant="outline" below textarea. Label: "Ask" when idle, disabled with text "Asking…" during fetch.
- Answer displayed below button in a `rounded-lg border border-zinc-800 bg-zinc-900 p-4` block.
- Answer text: `text-sm text-zinc-300 whitespace-pre-wrap font-mono` (plain text, preserve newlines from LLM).
- No markdown rendering — whitespace-pre-wrap handles line breaks.
- Loading state: button disabled + text "Asking…" + answer block shows `animate-pulse` dots.
- Error state: answer block shows error copy in `text-red-400`.
- Previous answer cleared on new submission.
- No conversation history persisted.

### Stale state

- Entire Intelligence tab section applies `opacity-50` when `isStale` (consistent with OverviewPanel and ModelCard).
